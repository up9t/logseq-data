- In Go programming language, there are 3 different types of channel based on its read and write: Bidirectional Channel (Read & Write), Read/Receive-only channel, and Write-only channel. When initialize a channel with `make()`, normally we use the standard channel (bidirectional), because creating read-only channel would mean no data can be write to it.
-
- ```go
  myChannel := make(chan int) // create a read and write channel
  
  // this function can only read to the channel but not write data to it.
  // The compiler will throw an error if it detects this function writing data to the channel.
  func A(ch <-chan int) {
  }
  
  // the opposite, can't read data, only able to write to it.
  func B(ch chan<- int) {
  }
  ```
-
- ## Buffered vs Unbuffered Channel
-
- There are also `unbuffered` and `buffered` channel.
-
- **Buffered** means have capacity. If a sender sends data to the buffered channel, it won't wait/block until there is receiver unless the channel is full, if it is full the sender needs to wait for an empty space which means waiting the data to be picked up by a receiver.
-
- **Unbuffered** means doesn't have capacity (capacity = 0). It doesn't store the data in the channel, instead the data will be copied directly from the sender to the receiver by the Go runtime. That's why in unbuffered channel, the sender needs to wait for a receiver.
